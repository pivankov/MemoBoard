# MemoBoard Backend

Backend-часть приложения MemoBoard - система для управления событиями и закладками.

## 🚀 Технологии

- **Node.js** 18+
- **Express** 5.x - веб-фреймворк
- **SQLite** 3.x - база данных
- **better-sqlite3** - синхронный драйвер для SQLite
- **nanoid** - генерация уникальных идентификаторов
- **url-metadata** - парсинг метаданных URL
- **sharp** - обработка и оптимизация изображений (превью закладок)
- **argon2** - хеширование паролей

## 📦 Установка и запуск

### Требования

- Node.js версии 18 или выше
- npm

### Установка зависимостей

```bash
npm install
```

### Инициализация базы данных

```bash
# С тестовыми данными (рекомендуется для разработки)
npm run db:init

# Без тестовых данных
npm run db:init:noseed

# Полный сброс БД с тестовыми данными
npm run db:reset
```

### Запуск сервера

```bash
npm start
```

Сервер запустится на порту `4000` (по умолчанию).

### Health Check

Проверка работоспособности сервера:

Создает новое событие.

**Тело запроса:**

**Ответ (201):**

- `400` - Некорректные данные (заголовок, дата, тип или recurrence)
- `500` - Не удалось создать событие

#### POST /api/bookmarks

Создает новую закладку с автоматическим парсингом метаданных URL.

**Тело запроса:**
```json
{
  "url": "https://example.com",
  "categoryId": "cat1"
}
```

**Поля:**
- `url` (string, required) - URL закладки
- `categoryId` (string, optional) - UID категории. Если не передан или `null`, закладка создаётся без категории и попадает в выдачу `GET /api/bookmarks/unsorted`

**Ответ (201):**
```json
{
  "success": true
}
```

**Описание:**
При создании закладки сервер автоматически:
1. Пытается получить метаданные страницы (title, description, og:image) через парсинг Open Graph, Twitter Cards и стандартных meta-тегов. Если парсинг не удаётся, используется URL в качестве заголовка.
2. Извлекает URL превью из `og:image` или `twitter:image` метаданных.
3. Если preview-изображение не найдено в метаданных — использует favicon сайта (`/favicon.ico`).
4. Скачивает изображение, оптимизирует его (ресайз до 200×200px, конвертация в WebP) и сохраняет в `uploads/previews/`.
5. Сохраняет относительный путь к файлу в поле `preview` записи в БД.

Если загрузка превью не удалась по любой причине, закладка всё равно создаётся — поле `preview` остаётся пустым. Иконки (`.ico`) сохраняются без конвертации.

Запрос метаданных выполняется с браузерным User-Agent, поскольку часть сайтов (например npmjs.com) блокирует запросы с дефолтным Node.js User-Agent и не возвращает `og:image` в ответе.

**Ошибки:**
- `400` - URL не указан / некорректный идентификатор категории / категория не найдена
- `500` - Не удалось создать закладку

---

#### PUT /api/bookmarks/:id

Обновляет существующую закладку.

**Параметры:**
- `id` (string, required) - UID закладки

**Тело запроса:**
```json
{
  "url": "https://example.com",
  "title": "Обновленный заголовок",
  "description": "Обновленное описание",
  "categoryId": "cat1",
  "existingTagIds": ["abc12", "def34"],
  "newTagTitles": ["новый тег"],
  "preview": "https://example.com/preview.jpg",
  "favorite": true,
  "inTrash": false
}
```

**Поля:**
- `url` (string, required) - URL закладки
- `title` (string, required) - Заголовок закладки
- `description` (string, optional) - Описание
- `categoryId` (string, required) - UID категории
- `existingTagIds` (string[], optional) - Массив UID существующих тегов для привязки
- `newTagTitles` (string[], optional) - Массив названий новых тегов для создания и привязки
- `preview` (string, optional) - URL превью изображения
- `favorite` (boolean, optional) - Избранное
- `inTrash` (boolean, optional) - Статус корзины. Для управления корзиной предпочтительнее использовать `PATCH /api/bookmarks/:id/trash`

**Ответ (200):**
```json
{
  "success": true
}
```

**Описание:**
Теги передаются двумя раздельными массивами. `existingTagIds` содержит UID уже существующих тегов. `newTagTitles` содержит названия новых тегов — они создаются автоматически и сразу привязываются к закладке. Все старые связи с тегами удаляются и пересоздаются. Вся операция выполняется в единой транзакции. Если тег из `existingTagIds` не найден, он пропускается с предупреждением в лог.

**Ошибки:**
- `400` - Некорректные данные / existingTagIds или newTagTitles не массивы / категория не найдена
- `404` - Закладка не найдена
- `500` - Не удалось обновить закладку

---

#### PATCH /api/bookmarks/:id/trash

Перемещает закладку в корзину или восстанавливает её из корзины.

**Параметры:**
- `id` (string, required) - UID закладки

**Тело запроса:**
```json
{
  "inTrash": true
}
```

**Поля:**
- `inTrash` (boolean, required) - `true` — переместить в корзину, `false` — восстановить из корзины

**Ответ (200):**
```json
{
  "success": true
}
```

**Описание:**
При перемещении в корзину поле `category_id` закладки **не изменяется** — оригинальная категория сохраняется. При восстановлении (`inTrash: false`) закладка возвращается в свою прежнюю категорию. Окончательное удаление выполняется через `DELETE /api/bookmarks/:id`.

**Ошибки:**
- `400` - Некорректный идентификатор / поле `inTrash` не передано или не является boolean
- `404` - Закладка не найдена
- `500` - Не удалось обновить статус корзины

---

#### DELETE /api/bookmarks/:id

Удаляет закладку по идентификатору.

**Параметры:**
- `id` (string, required) - UID закладки

**Ответ (200):**
```json
{
  "success": true
}
```

**Описание:**
При удалении закладки автоматически:
- Удаляется файл превью с диска (если он был сохранён в `uploads/previews/`)
- Удаляются все связи с тегами (CASCADE)

**Ошибки:**
- `400` - Некорректный идентификатор
- `404` - Закладка не найдена
- `500` - Не удалось удалить закладку

#### POST /api/bookmarks/categories

Создает новую категорию или коллекцию.

**Универсальный метод** для создания:
- **Коллекция** (родительская категория) - если `parentId` не передан или `null`
- **Категория** (вложенная) - если `parentId` указан

При создании автоматически вычисляется позиция (`position`) как `MAX(position) + 1` среди категорий того же уровня.

**Тело запроса:**
```json
{
  "title": "Разработка",
  "icon": "code",
  "parentId": null
}
```

**Поля:**
- `title` (string, required) - Название категории/коллекции
- `icon` (string, optional) - Иконка (только для категорий, для коллекций игнорируется)
- `parentId` (string|null, optional) - UID родительской категории (null или отсутствует для коллекции)

**Ответ (201):**
```json
{
  "success": true
}
```

**Примеры использования:**

*Создание коллекции:*
```json
{
  "title": "Разработка"
}
```

*Создание категории внутри коллекции:*
```json
{
  "title": "Frontend",
  "icon": "react",
  "parentId": "cat1"
}
```

**Ошибки:**
- `400` - Некорректные данные / родительская категория не найдена
- `500` - Не удалось создать категорию

```json
}
```

**Поля:** (минимум одно обязательно)
- `title` (string, optional) - Название категории (не может быть пустой строкой или null)
- `icon` (string|null, optional) - Иконка категории (`null` удаляет иконку)

**Ответ (200):**
```json
{
  "success": true
}
```

**Примеры использования:**

*Обновление названия:*
```json
{
  "title": "Frontend"
}
```

*Установка иконки:*
```json
{
  "icon": "react"
}
```

*Удаление иконки:*
```json
{
  "icon": null
}
```

*Обновление названия и иконки одновременно:*
```json
{
  "title": "Frontend",
  "icon": "react"
}
```

**Ошибки:**
- `400` - Некорректный идентификатор / пустое название / некорректное значение иконки / не переданы поля для обновления
- `404` - Категория не найдена
- `500` - Не удалось обновить категорию

---

#### PATCH /api/bookmarks/categories/reorder

Batch-обновляет позиции и/или коллекцию у нескольких категорий/коллекций за один запрос.

Все изменения выполняются в одной транзакции SQLite — если хотя бы одна из переданных категорий не найдена, вся операция откатывается.

**Тело запроса:**
```json
{
  "items": [
    { "id": "uuid-1", "position": 0 },
    { "id": "uuid-2", "position": 1 },
    { "id": "uuid-3", "position": 2, "parentId": "uuid-collection" }
  ]
}
```

**Поля `items[]`:**
- `id` (string, required) - UID категории или коллекции
- `position` (number, required) - Новая позиция (неотрицательное целое число)
- `parentId` (string, optional) - Новый UID родительской коллекции; передаётся только при смене коллекции у категории

**Ответ (200):**
```json
{
  "success": true
}
```

**Примеры использования:**

*Изменение порядка коллекций:*
```json
{
  "items": [
    { "id": "col-2", "position": 0 },
    { "id": "col-1", "position": 1 },
    { "id": "col-3", "position": 2 }
  ]
}
```

*Изменение порядка категорий с переносом одной в другую коллекцию:*
```json
{
  "items": [
    { "id": "cat-1", "position": 0 },
    { "id": "cat-3", "position": 1, "parentId": "col-2" },
    { "id": "cat-2", "position": 2 }
  ]
}
```

**Ошибки:**
- `400` - `items` не является массивом или пустой / некорректный `id` элемента / некорректная `position` / некорректный `parentId`
- `404` - Категория или коллекция с указанным `id` / `parentId` не найдена
- `500` - Не удалось обновить порядок категорий

---

#### DELETE /api/bookmarks/categories/:id

Удаляет категорию или коллекцию по идентификатору.

**Универсальный метод** для удаления как коллекций, так и категорий.

Перед удалением выполняются проверки:
- **Для коллекции** (`parentId = null`): нельзя удалить, если есть дочерние категории
- **Для категории** (`parentId != null`): нельзя удалить, если есть прикрепленные закладки

**Параметры:**
- `id` (string, required) - UID категории/коллекции

**Ответ (200):**
```json
{
  "success": true
}
```

**Примеры ошибок:**

*Попытка удалить коллекцию с категориями:*
```json
{
  "error": "Невозможно удалить коллекцию. Сначала удалите все категории внутри неё"
}
```

*Попытка удалить категорию с закладками:*
```json
{
  "error": "Невозможно удалить категорию. Сначала удалите все закладки из неё"
}
```

**Ошибки:**
- `400` - Некорректный идентификатор / есть связанные данные (дочерние категории или закладки)
- `404` - Категория/коллекция не найдена
- `500` - Не удалось удалить категорию

**Описание:**
Метод автоматически определяет тип удаляемого элемента (коллекция или категория) по полю `parent_id` и выполняет соответствующие проверки перед удалением. Это предотвращает нарушение целостности данных.

## 🛠 Утилиты

### utils/preview.js

Утилиты для работы с превью изображениями закладок.

Превью скачиваются при создании закладки и хранятся в `uploads/previews/`. Изображения оптимизируются через `sharp`: ресайз до 200×200px с сохранением пропорций, конвертация в WebP (качество 80%). Иконки (`.ico`) сохраняются без обработки.

**Функции:**
- `extractPreviewUrl(metadata)` - Извлекает URL превью из метаданных (`og:image` → `twitter:image`)
- `downloadPreview(imageUrl, bookmarkUid)` - Скачивает изображение, оптимизирует и сохраняет локально. Возвращает относительный путь `/previews/uid.ext` или `null` при ошибке
- `deletePreview(previewPath)` - Удаляет файл превью с диска. Отсутствие файла не является ошибкой
- `getFaviconUrl(url)` - Возвращает URL favicon сайта (`{protocol}://{host}/favicon.ico`)

**Особенности:**
- Папка `uploads/previews/` создаётся автоматически при первом скачивании
- Таймаут скачивания: 10 секунд
- Максимальный размер файла: 5 MB
- Поддерживаемые форматы входных данных: JPEG, PNG, WebP, GIF, ICO
- Формат сохранения: WebP (для JPEG/PNG/WebP/GIF) или ICO (без изменений)
- Все ошибки логируются через `console.warn`, исключения не пробрасываются

**Пример:**
```javascript
import { extractPreviewUrl, downloadPreview, getFaviconUrl } from './utils/preview.js';

const previewUrl = extractPreviewUrl(metadata);
// => "https://example.com/og-image.jpg" или null

const previewPath = await downloadPreview(previewUrl, 'xK9pLm2n');
// => "/previews/xK9pLm2n.webp" или null

const faviconUrl = getFaviconUrl('https://github.com');
// => "https://github.com/favicon.ico"
```

---

### utils/date.js

Утилиты для работы с датами.

**Функции:**
- `normalizeInputDate(dateInput)` - Нормализует входящую дату к ISO-строке с таймзоной UTC

**Пример:**
```javascript
import { normalizeInputDate } from './utils/date.js';

normalizeInputDate('2024-06-13');
// => "2024-06-13T00:00:00Z"

normalizeInputDate('2024-06-13T15:30:00');
// => "2024-06-13T15:30:00.000Z"
```

### utils/uid.js

Утилиты для генерации уникальных идентификаторов.

**Функции:**
- `generateBookmarkUid()` - Генерирует уникальный UID для закладки (8 символов)
- `generateCategoryUid()` - Генерирует уникальный UID для категории (4 символа)
- `generateTagUid()` - Генерирует уникальный UID для тега (5 символов)

**Особенности:**
- Использует библиотеку nanoid для генерации
- Проверяет уникальность в базе данных
- Делает до 10 попыток при коллизии

**Пример:**
```javascript
import { generateBookmarkUid, generateTagUid } from './utils/uid.js';

const bookmarkUid = generateBookmarkUid();
// => "xK9pLm2n"

const tagUid = generateTagUid();
// => "a3X7k"
```

## 📝 Дополнительная информация

### Middleware

Приложение использует следующие middleware:
- `express.json()` - Парсинг JSON в теле запроса
- `express.urlencoded({ extended: true })` - Парсинг URL-encoded данных
- `cors()` - Включение CORS для всех источников
- `express.static('/previews')` - Раздача превью закладок из папки `uploads/previews/`
- `express.static()` - Раздача статических файлов сборки фронтенда из папки `public`

### Обработка ошибок

Все endpoint'ы возвращают ошибки в едином формате:
```json
{
  "error": "Описание ошибки"
}
```

Ошибки также логируются в консоль с помощью `console.error()`.

### Валидация данных

Валидация происходит на уровне route handlers:
- Проверка типов данных
- Проверка обязательных полей
- Проверка допустимых значений (например, recurrence)
- Проверка существования связанных сущностей (типы событий, категории, теги)
