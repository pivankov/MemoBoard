# Cursor Rules для MemoBoard

## Общие правила
- Отвечай на русском языке
- Учитывай линтеры при формировании кода
- Перед тем как внести изменения, опиши общий план реализации по пунктам и после преступай к реализации
- В конце каждого ответа, указывай какой ИИ агент отвечал на вопрос
- Не пиши документацию без запроса. Если есть необходимость в написании документации, предложи, но приступать к работе без одобрения нельзя.

## Контекст проекта

  ### Стек технологий
  - Frontend: React + TypeScript + Ant Design
  - Backend: Node.js + Express + SQLite
  - Database: SQLite

  ### Приложения
  - Cобытия (Календарь событий с повторениями)

## Технические требования
- TypeScript strict mode
- React 18+ с hooks
- Ant Design 5.x

## Принципы
- Приоритет читаемости кода
- Использование TypeScript
- Обработка ошибок линтера
- Мемоизация для производительности
- Именование компонентов PascalCase (EventsListItem.tsx)
- Именования хуков camelCase с префиксом use (useGroupedEvents.ts)
- Именования утилит camelCase (date.ts, events.ts)

## Стиль кода
- Использовать функциональные компоненты
- Prefer const over let
- Использовать arrow functions
- Избегать any, использовать строгие типы
- Один компонент = один файл

## Документация кода
- Использовать JSDoc для публичных типов, функций и методов
- Стиль комментариев: емко, но информативно
- Структура JSDoc:
  - Краткое описание назначения (1-2 строки)
  - @param с пояснением назначения параметра
  - @returns с описанием возвращаемого значения
  - Дополнительные пояснения в отдельных абзацах при необходимости
  - Критические моменты выделять отдельно
- Избегать очевидных комментариев и избыточного описания
- Примеры значений добавлять инлайн-комментариями в типах

## Система событий
- Типы повторения: none, monthly, yearly
- Использовать useGroupedEvents для группировки
- Валидация дат обязательна

## Хуки
- Использовать useMemo для дорогих вычислений
- Использовать useCallback для функций в зависимостях
- Избегать useEffect без зависимостей

## Тестирование
- Использовать Jest для unit-тестов
- Файлы тестов: `*.test.ts`, `*.test.tsx`
- Хелперы для тестов: `*.helper.ts`
- Тесты размещать в `__tests__` папках
- Хелперы тестов рамещены в `__tests-helpers__`
- Использовать фиксированные даты в тестах (параметр today)
- Покрывать критические edge cases

## Структура

  ### События
  - `backend/routes/events/index.js` - API endpoints
  - `types/events.ts` - типы данных
  - `useEvents.ts` - API взаимодействие
  - `useGroupedEvents.ts` - основная логика группировки событий. Документация хука `frontend/docs/useGroupedEvents.md`

## Предложения по инструментам Cursor

В конце ответа кратко предлагай создать инструмент, если есть явный признак:

- **Навык** — одна и та же инструкция встречается уже второй раз, или задача требует знания неочевидных соглашений проекта
- **Субагент** — задача многошаговая и результат стоит проверить независимо, или несколько частей можно выполнить параллельно
- **Хук** — есть риск необратимого действия (удаление данных, сброс БД), или нужна автоматическая реакция на событие агента

Предложение — одна строка в конце ответа. Не создавай инструмент без явного одобрения.
